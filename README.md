# notetab

Веб-конвертер **гитарных табулатур ↔ нот**: перевод таба в ноты с таблицей и звуком и обратный перевод мелодии в **несколько вариантов аппликатуры**.

Статический сайт без сборки и зависимостей: чистые ES-модули, весь расчёт в браузере, офлайн. Никакого бэкенда, CDN и внешних шрифтов.

**Живой сайт:** https://irinatunes.github.io/notetab/

## Что умеет

**1. Таб → ноты**
- Принимает ASCII-таб: 6 строк, подписи `e B G D A E` (1-я строка — тонкая струна). Подпись до первого `|` и последний `|` отбрасываются, строки выравниваются.
- Ноты одной колонки считаются аккордом и сортируются по высоте.
- Результат — таблица: нота, октава, MIDI, струна, лад, русское название (`C#4` и «до-диез первой октавы»).
- Кнопки: **▶ Прослушать** (WebAudio, синус с огибающей), **⬇ .txt**, **⬇ .csv**, **⬇ .mid**.
- Ошибки текстом: не 6 строк, лад больше 15, нота вне диапазона гитары, пустой таб.

**2. Ноты → таб (несколько вариантов)**
- Ввод нот латиницей или по-русски, слитно или через пробел: `E4 E4 F4 G4`, `ми4 фа4 соль4`, `E4E4F4`, `C#4`, `до-диез4`, `ля-бемоль3`.
- Параметры: строй, максимальный лад (5–15, по умолчанию 12), растяжка (3–5 ладов, по умолчанию 4).
- Результат — 3–6 карточек с **разными аппликатурами**; у каждой: заголовок, описание («позиция 1–3, 0 переходов», «открытых струн: 3»), моноширинный предпросмотр и кнопки **▶**, **⬇ .txt**, **⬇ .mid**, **⬇ .json**.

**3. PDF → таб (локальный сервис)**

- Скан или PDF с **ТАБ-станами** → распознанный ASCII-таб. Работает через локальный сервис `omr-service/` на `127.0.0.1:8765`, который запускается одной командой (см. раздел «PDF → таб»).
- Результат показывается в **редактируемом поле**: OCR иногда склеивает цифры, поэтому таб обязательно проверяется руками.
- Кнопка **«Получить варианты аппликатуры»** прогоняет распознанный таб через тот же `parseTab` + `notesToTabs` и показывает карточки вариантов.
- Экспорт: **⬇ .txt**, **⬇ .json**, **⬇ .musicxml** (MusicXML 3.1, TAB-ключ, 6 линий, `string`/`fret`), **⬇ .mid**, **🖨 PDF** (A4-макет в новом окне + `window.print()`).

## Как считаются варианты

Перебор — beam search по кандидатам «струна + лад» для каждой ноты (нота есть на струне, если `midi_струны + лад == midi`). Состояние поиска: окно руки (min/max лад), опорный лад, число переходов и открытых струн. Ширина бим-поиска — 8 состояний, дедупликация состояний по окну.

Разные функции стоимости дают разные аппликатуры:

| Вариант | Что оптимизируется |
|---|---|
| Компактная позиция | минимальный сдвиг руки, при равенстве — меньший лад |
| Открытые струны | сильный бонус за лад 0 |
| Фиксированная позиция 1–5 / 3–7 / 5–9 / 7–12 | перебор окон, берутся два лучших (по стоимости), ноты вне окна запрещены |
| Мелодия на верхних струнах | предпочтение 1–2 струн |
| Нижние струны (густой тембр) | предпочтение толстых струн |

Если рука выходит за растяжку, окно сбрасывается на новую позицию и добавляется штраф за переход — так считаются «переходы» в описании.

Результаты **дедуплицируются по тексту таба**: два варианта с одинаковой аппликатурой остаются одним. Поэтому карточек может быть меньше шести — это не ошибка, а совпадение решений. Для коротких мелодий, где позиции почти не отличаются, добавляется «Альтернативная аппликатура» — та же фраза с другой струной для одной ноты.

## Пример

Вход: `E4 E4 F4 G4 G4 F4 E4 D4`

Вариант 1 — компактная позиция (позиция 1–3, 0 переходов):

```
e|0-0-1-3-3-1-0---|
B|--------------3-|
G|----------------|
D|----------------|
A|----------------|
E|----------------|
```

Вариант 2 — фиксированная позиция 3–7:

```
e|0-0---3-3---0---|
B|----6-----6---3-|
G|----------------|
D|----------------|
A|----------------|
E|----------------|
```

Обратный перевод (пример из интерфейса):

```
e|----------------|
B|-------------0--|
G|-----0--2--0----|
D|--2-------------|
A|----------------|
E|----------------|
```

даёт ноты `E3 G3 A3 G3 B3` = MIDI 52, 55, 57, 55, 59, у каждой в таблице указаны струна и лад: E3 — 4-я струна, 2-й лад; G3 — 3-я, открытая; A3 — 3-я, 2-й лад; B3 — 2-я, открытая.

## PDF → таб

Вкладка **«PDF → таб»** принимает скан или PDF с табулатурой и возвращает ASCII-таб. Это не облачный сервис: распознавание идёт в отдельном локальном процессе, браузер обращается к нему напрямую.

### Запуск сервиса (одна команда)

```bash
cd omr-service && ./run.sh
```

Первый запуск сам создаёт `.venv` и ставит `numpy` + `pillow`. Сервис слушает **только** `127.0.0.1:8765`; проверка живости — `curl http://127.0.0.1:8765/health` → `{"ok":true,"version":"0.1.0"}`.

Нужны во внешнем окружении:

```bash
brew install poppler tesseract      # macOS
sudo apt install poppler-utils tesseract-ocr   # Debian/Ubuntu
```

Если сервис не запущен, вкладка не падает: показывает блок «Локальный сервис не запущен» и эту же команду запуска.

**Если сервис запущен, но браузер не даёт к нему обратиться.** Chrome (Local Network Access) и новые Safari блокируют запросы со страницы `https://…` к `127.0.0.1`; в консоли это `TypeError: Failed to fetch`, хотя `curl http://127.0.0.1:8765/health` отвечает. Варианты:

1. Разрешить доступ, когда браузер спросит про «локальную сеть» (Chrome: иконка слева от адреса → «Local network access» → Allow), затем нажать «Проверить снова».
2. Открыть сайт локально — с `http://localhost` запрос к сервису проходит (проверено в Chrome):

```bash
python3 -m http.server 8080   # → http://localhost:8080
```

### Что распознаётся

- **ТАБ-станы** — 6 горизонтальных линий на странице; определяется адаптивно (5 линий = нотный стан, 6 = таб), шаг линий у изданий разный.
- **Цифры ладов** — OCR всей страницы (`psm 11`, whitelist цифр и скобок флажолета) при увеличении ×2. Номер струны определяется по ближайшей линии, колонки собираются по x с допуском 12 px.
- **Флажолеты** в записи `<7>`, `(12)` — читаются как лад 7 и 12.
- Несколько систем на странице склеиваются в один таб; страницы складываются подряд.

### Что НЕ распознаётся

- **Нотный стан без таба** — высоты по нотам не читаются (полный OMR не используется: Audiveris не понимает ТАБ-станы и путает высоты на полтона).
- **Рукописные табы** — OCR рассчитан на печатный шрифт.
- **Ритм** — в табе его нет, длительности не переносятся (в MusicXML все ноты — четверти, темп 120).
- **Аппликатура пальцев** (цифры 1–4 под станом), штрихи, бенды, хаммеры — отбрасываются как мусор.
- Лад больше 24 считается ошибкой OCR и отбрасывается (34, 49, 72 — типичные склейки).

### Проверка обязательна

OCR иногда склеивает соседние цифры (`1` + `3` → `13`) или теряет часть символов. Поэтому распознанный таб открывается в **редактируемом поле**: сверьте его с исходником, поправьте и только потом жмите «Получить варианты аппликатуры». Предупреждения над полем показывают, сколько токенов отброшено и на каких страницах не нашлось таба.

### API

```bash
curl -s http://127.0.0.1:8765/health

curl -s -X POST --data-binary @scan.pdf -H "Content-Type: application/pdf" \
     http://127.0.0.1:8765/tab/pdf | jq '{pages: (.pages|length), warnings, combined_tab}'
```

`POST /tab/pdf` принимает и raw body (`application/pdf` + необязательный `X-Filename`), и `multipart/form-data`; `X-Pages: 1,3` ограничивает страницы. Ответ: `{pages:[{page, staves, tokens, dropped, tab}], combined_tab, warnings}`.

`POST /omr/pdf` — экспериментальный путь для нотных изданий: если найден `Audiveris.app` (env `AUDIVERIS_APP` или `/Users/irina/projects/omr-spike/Audiveris.app`), возвращает MusicXML; иначе `501` с объяснением. Обязательным он не является.

### Экспорт результата

| Формат | Что внутри |
|---|---|
| `.txt` | ASCII-таб + список нот (струна, лад) |
| `.json` | таб, ноты, строй, предупреждения, разбор по страницам |
| `.musicxml` | MusicXML 3.1 partwise: `<divisions>4`, 4/4, `<sign>TAB</sign>` + `clef-octave-change -1`, `<staff-lines>6</staff-lines>`, у каждой ноты `<pitch>` и `<technical><string>/<fret>` |
| `.mid` | SMF type 0 (как во вкладке «Таб → ноты») |
| PDF | A4-макет в новом окне: заголовок, строй, крупный моноширинный таб (режется по системам под ширину страницы), список нот, кнопка «Печать / Сохранить в PDF» |

## Строи

| Строй | MIDI струн 1→6 |
|---|---|
| Стандартный E A D G B E | 64, 59, 55, 50, 45, 40 |
| Drop D D A D G B E | 64, 59, 55, 50, 45, 38 |
| На полтона ниже Eb Ab Db Gb Bb Eb | 63, 58, 54, 49, 44, 39 |

## Ограничения (честно)

- **Ритм не хранится.** Таб и список нот — это только высоты; длительности, паузы, штрихи теряются. MIDI пишется равными долями (1 нота = 1 доля, 96 PPQ, 120 BPM).
- **Аппликатура неоднозначна.** Одну и ту же мелодию можно сыграть десятком способов; все варианты равноправны, «правильного» нет — выбирайте удобный руке.
- **Лады 0–15.** В табе лад больше 15 — ошибка. При генерации максимальный лад ограничен 5–15.
- **Только гитара**, 6 струн, диапазон MIDI 38–86 (D2–D6). Бас, укулеле, 7-струнка не поддерживаются.
- Таб разбирается посимвольно: аккорды должны быть выровнены по вертикали, как в обычной ASCII-табулатуре.

## Тесты

```bash
node --test                     # 40 тестов JS
python -m pytest omr-service/tests -q   # 11 тестов Python
```

JS — без браузера (`src/*.js` — обычные ES-модули, Node читает их напрямую):

- гамма до мажор по грифу даёт ровно `[55,57,59,60,62,64,65,67,69]`;
- round-trip ноты → таб → ноты сохраняет высоты;
- `notesToTabs` возвращает ≥ 3 варианта, все тексты различаются;
- каждая нота каждого варианта существует на своей струне (проверка по строю);
- ошибки: не 6 строк, лад > 15, нота вне диапазона;
- MIDI: `MThd`, длина заголовка 6, `MTrk`, согласованная длина;
- MusicXML: well-formed, TAB-ключ, 6 `staff-lines`, `string`/`fret` у каждой ноты, темп 120, пустой список не ломает документ;
- PDF-макет: A4, `@media print`, кнопка печати, пустой таб не падает, длинный таб режется по системам.

Python — на синтетической картинке Pillow (6 линий + цифры 0, 3, 5, 7): стан определяется как TAB, цифры извлекаются, колонки собираются, мусорные лады 34/49 и токены вне полосы отбрасываются. Тест с настоящим tesseract помечен skip, если бинарника нет.

## Структура

```
index.html              разметка, три вкладки
assets/styles.css       тёмная тема, мобильная вёрстка
assets/app.js           UI: разбор, таблица, звук, скачивание через Blob, загрузка PDF
src/notes.js            ноты: латиница/кириллица, диезы, октавы, MIDI
src/tuning.js           строи
src/tab.js              генерация и разбор ASCII-таба
src/solver.js           beam search и варианты аппликатуры
src/midi.js             SMF type 0 без библиотек
src/musicxml.js         MusicXML 3.1 partwise с TAB-партией
src/printable.js        A4-макет для печати (HTML + @media print)
omr-service/server.py   локальный HTTP-сервис (http.server, 127.0.0.1:8765)
omr-service/tabocr.py   конвейер: pdftoppm → линии → станы → OCR → колонки → таб
omr-service/run.sh      запуск одной командой (venv + зависимости)
omr-service/tests/      pytest: геометрия, фильтры, сборка, OCR синтетики
scripts/export-check.mjs проверка экспортов на реальном JSON от сервиса
test/*.test.js          node --test
```

## Локальный запуск

```bash
python3 -m http.server 8080   # затем http://localhost:8080
cd omr-service && ./run.sh     # во втором терминале — для вкладки «PDF → таб»
```

`file://` тоже работает (ES-модули грузятся по относительным путям).
